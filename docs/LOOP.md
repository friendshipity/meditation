# Loop Design

## 单轮协议

每一轮都应包含以下阶段：

1. **Receive**
   - 输入：用户主题/问题。

2. **Assess**
   - 判断是否需要外部搜索。
   - 若不必要，直接进入联想阶段。

3. **Search (Optional)**
   - 仅在必要时调用 `web_search`。
   - 受 `5 次/小时` 硬限制。

4. **Think (Associative)**
   - 围绕输入和已有记忆进行相关联想。
   - 不要求单轮必须收敛到“最终答案”。

5. **Summarize**
   - 输出本轮阶段性总结。

6. **Ask-back**
   - 生成一个高质量反问，作为下轮用户输入。

7. **Memory Update**
   - 将本轮关键内容写入记忆，并执行压缩。

## 多轮目标

- 通过反问链条维持探索动量。
- 在多轮内形成更深层次结构化理解。
- 逐步减少“重复搜索”，提高内审质量。

## 终止条件（可配置）

- 达到用户预设轮数。
- 用户主动停止。
- 主题已经稳定收敛，反问价值下降。
